# Telos S4 ordinary role bindings

S4 binds ordinary chats to an explicit item and reviewed context. It uses the
existing session identity, settings, repository preparation, renderer, composer,
Resources and lifecycle. Opening an item or reviewing its source creates no chat,
assignment, attempt or model command.

Choose lead/worker opens an ordinary draft. Agent, Account, Model, Thinking, Run on,
derived Runs with and repository preparation remain the ordinary controls. Explicit
assignment creates a new ordinary conversation; replacement retains all older
conversations and attribution. New chat adds a role link without replacing the
current assignment. Advisor and historical navigation never assign a worker.

The versioned role context records the exact item brief, public ancestor criteria,
overall goal, selected source snapshots and material revisions. Ordinary guidance
is compiled into Local/OpenShell initial and continuation packets and verified again
at final admission. Task host operations reject execution through lead/advisor/
reviewer chats. Worker Task Board execution requires an exact retained task identity;
S4 does not invent that mapping or implement S5 allocation/dispatch. Ordinary tool
permissions still belong to the selected ordinary profile; this is not a new general
purpose sandbox or arbitrary transcript access grant.

Setup durably retains its request identity before ordinary preparation. Exact retries
recover the same session and receipt after interruption. Competing replacements,
changed actors/settings, stale revisions and revoked authority fail explicitly.
Committed receipts survive later authority loss; access loss does not erase a commit.
The authenticated HTTP operations have no generic conversation-to-work write port.

Refine item and Add child open full ordinary advisor chats. The proposal card remains
inside the ordinary transcript. Save reviews the completed planning discussion through
the accepted source compiler, then atomically retains its source, item fields/link and
receipt. Refinement preserves item kind, criteria, rationale and secondary categories.
Child save creates an explicitly typed source-only draft. Leaf work items expose
Refine item; Add child belongs to explicit parent kinds. The host rejects a new child
advisor for a work item before ordinary preparation. Exact committed role receipts
remain recoverable after later kind changes, without rewriting their original purpose.
Neither operation dispatches
work. Interrupted save retries its retained request and source digest. Proposal fields
retain the starting item/parent revisions; a concurrent edit is refused without losing
the proposal. Capture uses the last message's exact retained completion anchor, never
the transcript high-water cursor. Interrupted or synthetic history has no such anchor;
public-error prefix refusals remain enforced by the source compiler.

A saved child's selected source may retain exact material revisions owned by its
parent. Reuse requires proof from that child's verified source packet and current
public-owner eligibility; this grants no other parent or sibling material access.
Both ordinary pages require a successful rich-draft flush before setup and again
after awaited setup, before draft binding or navigation.

## Qualified boundaries

Silent setup currently uses the qualified Codex Local/OpenShell repository preparation
owners. Unsupported accounts, runtimes, unavailable preparation/capacity authorities
and changed immutable bindings remain explicit refusals. S4 does not enable the public
joining route or claim universal account/runtime support.

The source namespace, ordinary conversation ID, provider continuation ID, client,
Telos item and execution identity remain distinct. External Codex origins remain
external. Item context does not authorize sibling/private transcript discovery.
