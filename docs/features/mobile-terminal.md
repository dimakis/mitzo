# Mobile terminal and Minion

Open **More → Terminal** to resume the Mac shell, or choose **Terminal** in a chat’s composer tools menu to open that conversation’s environment. Both entries use the same page and the existing mobile masthead. Back returns to the conversation without ending the shell. Controls and Minion collapse independently, and the command area stays reachable when the phone keyboard opens.

The destination selector offers the Mac and a search over named chat sandboxes. It never accepts a client-supplied directory, gateway or sandbox ID. A sandbox must have a saved runtime receipt, unchanged account/runtime configuration and an observed Ready physical instance. Ambiguous multi-agent conversations require a specific agent destination and currently fail closed.

## Shell lifecycle

The host and eligible sandboxes need `tmux` on PATH. Mitzo attaches a node-pty client to its own tmux namespace. Navigating away only removes the output subscriber; application shutdown detaches clients while tmux preserves the shell. Reconnect and server reconstruction attach the recorded session. Ownership lasts for the authenticated login: logout or expiry closes its shells. Durable login leases and original cleanup receipts allow expiry reconciliation after server restart; uncertain cleanup retains capacity and retries with persistent backoff from one minute to one hour, outside the shell-opening queue and without retargeting another sandbox. A missing saved shell never becomes a new shell implicitly. **End terminal session** ends it explicitly.

Terminal records live in the existing task-store database and are owned by the interactive login that opened them. A different login cannot list, read, write, resize or end those records. Limits are five running shells per login and fifty overall. Output replay is bounded. Logout and expiry close streams and cancel queued input before delivery.

Sandbox SSH uses the reviewed OpenShell v1 `CreateSshSession` wire contract to mint a short-lived grant for the saved **physical sandbox ID**, then uses token-mode `ssh-proxy`. Recycled names cannot redirect a shell. This requires the runtime’s explicit private CLI HOME and its verified mTLS gateway metadata. Unsupported authentication/configuration fails without a host or name-based fallback. The grant stays in the transport process; it is not stored in the terminal database or returned to the browser. The wire layout is pinned to [the reviewed OpenShell source](https://github.com/dimakis/OpenShell/blob/b4c459f92446167afcb0a2dcf7d9fa6c8945e59c/proto/openshell.proto).

The command area supports visible multiline drafts, explicit Run, Ctrl C, Esc and Tab, plus command recall and a history picker. Down restores an unfinished draft after recall. Suggestions and history fill the draft; they never execute it. Invisible terminal control characters are excluded from suggestions. History records only deliberate command-area submissions in the current app lifetime. Interactive login/password input goes directly through the TTY and is not added to that history.

## Adviser

Minion is collapsed initially. A chat supplies an initial account, model and thinking preference, independently of the terminal destination. Changing account or model starts a fresh adviser context; changing thinking retains the conversation. The shared AccountModelPicker supplies actual configured models and supported thinking choices without changing chat defaults. Gemini 3 uses supported named thinking levels. Gemini 2.5 adviser presets use budgets of 512 (low), 1024 (medium), and 2048 (high) tokens; Flash may also disable thinking. Unsupported choices, including minimal thinking without private thought signatures, are excluded from the adviser picker. For Gemini 3.1 and 3.5 Flash-Lite, Adviser default uses low thinking so follow-up text turns do not require unavailable private thought signatures.

**Share output** prepares selected text or recent rendered terminal lines in an editable review field. Nothing is sent until Ask. Remove secrets there before sending. The adviser has no terminal service, agent loop, execution dispatcher or tools. It makes a single native inference request and returns text and optional editable command suggestions. Provider tool calls fail closed. OpenAI and Gemini adviser adapters accept the explicitly reviewed text transcript on subsequent turns; agent sessions retain their stricter private-checkpoint contract.

OpenAI API, Gemini Vertex and Claude Vertex accounts are supported. The opt-in ChatGPT plan adapter uses a separate, text-only registration described below. Existing Codex/ChatGPT CLI account profiles are still excluded from the adviser catalog: their authentication and agent runtime do not establish permission for this inference route. Their saved eligible sandbox can still be the human terminal destination. No alternate account, model, API billing or host CLI credentials are substituted.

### ChatGPT plan adviser accounts

When the reviewed host configuration enables this integration, **Manage adviser accounts** appears inside the shared adviser picker. It stays collapsed until opened. Give the account a label and choose **Continue with ChatGPT on your Mac**. The host opens its system browser; consent and the loopback callback happen on the Mac even when Mitzo is open on the phone. Cancel sign-in is explicit. Reloading or returning to the terminal recovers the interactive operator’s pending attempt so it can still be checked or cancelled. A successful sign-in adds the account to the picker; choose its model and supported thinking mode before asking Minion.

The adapter follows OpenAI's [open-source registration flow](https://developers.openai.com/siwc/token-sharing-open-source/sign-in): `dynamic_agent_client` starts first registration, and the issued client ID is retained with the signed ID-token subject and stable host ID. Returning sign-in uses that registration and validates the same subject. It does not import a Codex auth file, borrow another app's client ID, export OAuth tokens to the phone, or expose an ID-token hint in a browser-visible API response. State, nonce, PKCE and the exact callback URI bind each attempt to its interactive operator; logout/expiry cancel it.

Permission for `chatgpt.tokens.use.direct` and `resource.invoke` is required. The selected registration's token discovers the [account-specific model catalog and performs inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference) through `https://api.openai.com/v1`. Only visible models are offered. Thinking levels/defaults are included when explicitly supplied by the provider catalog; they are never inferred from another account. The Responses request is a bounded text transcript with `store: false`, `stream: true`, no tools, no agent loop and no private checkpoint. It must reach successful completion; incomplete output, tool calls, usage errors and interrupted streams never become executable commands or trigger an API-billing fallback.

Credential storage belongs to one retained host writer. Files are protected, owner-only and atomically replaced; path guards exclude the whole private directory. A retained or uncertain lock requires host investigation and is never removed automatically. Verified sign-in credentials are saved before model discovery. Failed discovery retains the registration for returning sign-in or disconnect after restart, while keeping inference unavailable. Restart forces a signed refresh before inference; rotating credentials are persisted together before subsequent model discovery. Disconnect cancels pending reauthorization, invalidates active grants first, attempts provider revocation and clears local tokens while retaining the registration identity. Unconfirmed remote revocation is saved with the registration and remains visible after account refresh, navigation, restart and reauthorization, with instructions to disconnect Mitzo in ChatGPT Settings. Only confirmed provider revocation clears that warning. Reauthorization cannot let a superseded refresh invalidate the new grant.

The Mac bootstrap requires `MITZO_CHATGPT_PLAN_ADVISER_ENABLED=1` and an absolute, pre-created, canonical, owner-only `MITZO_CHATGPT_PLAN_ADVISER_DIR` in the independently reviewed staging configuration. There is no default credential directory, automatic enrollment or production activation. A temporary loopback OAuth callback listener exists only for the deliberate sign-in attempt; it is not a staging backend or preview service. Other platforms do not launch a host browser through this Mac adapter.

Personal Claude and Gemini subscriptions remain unavailable as adviser accounts. [Anthropic's SDK guidance](https://code.claude.com/docs/en/agent-sdk/overview) requires approval to offer claude.ai login or subscription limits in a third-party product. [Gemini's integration guidance](https://geminicli.com/docs/resources/faq/) directs third-party agents to supported API/Vertex credentials and disallows harvesting CLI OAuth credentials. Existing Claude Vertex and Gemini Vertex advisers continue to work; their consumer subscriptions are not represented as API/cloud credentials.

**Settings → Your minions → Terminal minion name** controls the terminal helper’s display name, defaulting to Minion. The briefing name is configured independently in the same section. Names are saved for the workspace across devices with revision checks; the terminal reads its name from `useHomePreferences`.

## Acceptance and rollout

Unit tests use synthetic provider events and TLS gateway fixtures. The native smoke test uses a temporary HOME, `/bin/sh` and a unique tmux socket, preserving a shell value across backend reconstruction and cleaning up only its own resources. Offline browser tests intercept every request and serve compiled assets without a backend or preview server; they cover Safari, phone Chromium and desktop Chromium, masthead geometry, explicit command execution, reviewed context and keyboard layout.

Live acceptance must use the canonical staging procedure after source acceptance and independently reviewed provider configuration. Any real model test must select a supported Luna model and state the exact model and charged account before calling it. This feature does not authorize production deployment, provider enrollment or an additional staging instance.
