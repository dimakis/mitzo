# Codex app-server in OpenShell spike

This directory contains only disposable-spike artifacts. It does not change the
Mitzo runtime, account profiles, or production services.

## Intended topology

One OpenShell sandbox is retained per Mitzo task workspace/Symposium. It holds
one or more cloned repositories under `/sandbox/workspaces`; collaborating
seats deliberately share that task data. The host-facing Mitzo controller owns
conversation metadata and approval records. A small bridge
starts `codex app-server` **inside** that sandbox and uses the app-server
`externalSandbox` policy for every `thread/start` and `thread/resume` request.

The sandbox must receive only task-scoped capability material, not integration
write credentials. A shared sandbox is the execution trust boundary: seat roles
and prompt filtering do **not** make files confidential from another seat. The
trusted controller or gateway provider is responsible for model/integration
authorization; a separate trusted executor performs approved external writes.
Separate seat sandboxes are a future option only when the product requires
different filesystem trust domains.

## Files

- `openshell-policy.yaml`: deny-by-default test policy.  It permits only the
  explicitly enumerated read endpoints after the operator extends it.
- `app-server-request.json`: representative `thread/start` request showing the
  externally sandboxed setting; it is a protocol fixture, not an account call.
- `run-disposable.sh`: creates a no-credential sandbox, performs harmless
  filesystem/network boundary checks, then deletes the sandbox on exit.
- `symposium-seat-fixture.*`: mocked two-seat contract showing separate
  account/model/context bindings and transcript provenance in one shared
  workspace. It is not a cross-provider live test.

Run the script only against an already working local OpenShell gateway.  It
does not configure providers or transmit secrets.

## Acceptance boundaries

The app-server schema generated by installed `codex-cli 0.153.4` includes
`{ "type": "externalSandbox" }`.  This proves the protocol capability, not
the outer OpenShell enforcement.  A pass requires the disposable command to
finish with `POSITIVE_FILESYSTEM=pass` and `NEGATIVE_NETWORK=pass` while the
sandbox exists, plus a separate authenticated account test performed without
mounting credential material.
