# Dormant artifact generation ledger

`SymposiumArtifactGenerations` is an isolated host ledger for a future accepted-fix
fork. It does not copy files, create volumes, admit seats, clear session fences,
release retention or dispatch models. It is not installed in the running host.

A trusted host supplies a stable private-custody SQLite database and synchronous,
affirmative proof callbacks for initial owned volume, current operator/seat
approval, completed immutable parent seal and actual terminal child-copy evidence.
References and hashes supplied to this ledger do not themselves prove those facts.
False, missing or asynchronous approval cannot advance a mutation.

The initial generation records its existing initialization receipt without
inventing a seal. A copy intent permanently binds parent generation, completed seal
reference, commit/tree/manifest/committed-tree digest and verified export bundle
hash; selected fix workflow/attempt/findings, operator/seat/account/model/profile
and authority revision; and copier image/code. Child volume, generation and helper
names are generated by the host ledger. The parent row is never rewritten.

Copy claim is persisted with FULL SQLite synchronization before future dispatch.
Only the first successful claim permits dispatch; replay returns false. The exact
helper ID must be retained before a successful terminal receipt can be recorded.
Observed helper identity and terminal evidence are retained before later approval
or proof checks can fail. Such observations alone do not authorize activation.
The receipt additionally binds child volume, initialization proof, imported Git
identity, fresh verification and helper removal. A separate mandatory host callback
must verify this against actual retained physical proof. Unknown or explicitly
quarantined operations cannot activate; quarantined operations have no retry or
recovery promotion API in this increment.

Activation revalidates authority, parent and child copy proof, then uses a CAS on
the independent working-generation pointer. A losing concurrent child stays
retained and inactive. Exact replay is idempotent. The prior generation remains
available by exact identity for historical cleanup/export. A historical `active`
state means that generation was activated; only the pointer identifies the current
working generation. No reviewed workflow artifact is advanced by this ledger.

## Verification and remaining work

Tests use real SQLite files, independent connections and competing Node processes.
They cover exact replay/conflicts, stale custody/authority/proofs, five restart
boundaries, unknown/quarantined copies, CAS activation and abrupt process death
after a durable claim. They make no provider calls or physical Podman mutations.

Remaining integration is substantial: reviewed bounded sealed Git export/import,
physical copier journal, generation-aware EventStore capabilities and seal intents,
historical cleanup bindings, fresh per-generation sandboxes, and parent validation
that survives an explicitly authorized successor. Existing session-wide fences stay
closed. Trusted native hard-budget enforcement and authoritative final accounting
remain prerequisites to model-backed accepted fixes and delta review.
