# Contained incident and a separately admitted native allocation

This source defines a separate, original-process native allocation protocol for
the exact retained October incident. Offline containment does not retire that
launch. Its row, logical plan path, history and archived bytes remain unchanged;
`nativeCleanupConfirmed` remains false. Registry policy stays at capacity one.

The new allocation uses `symposium/allocations/<UUID>` and an independent
registered `com.mitzo.staging` launcher. It cannot reopen the archived plan as a
live owner, adopt the released recovery guard, reuse an old native reservation or
receive native authority through bootstrap JSON. The bootstrap is a reviewed
data proposal, not an authorization capability.

The full saved combined recovery proposal must be retained privately outside all
inputs moved or mounted by recovery. The independent archive inspector matches
that exact proposal to completed native and ordinary intents, receipts, backups,
history, complete file manifests and physical archive closure. It checks actual
old boot/control identities, unmounted/unopened archived inputs and preserved
machine bytes. Missing facts produce a refusal; an offline archive is never a
replacement VM ownership proof.

The actual entry is `scripts/start-contained-native-staging.mjs`. It runs only as
the first exact registered source-owned canonical actor, with its exact private
bootstrap path and SHA. Source code composes the helper, inspector, new guard,
ledger, original registry lease, local-image inspector, fresh stock provisioner
and original VM owner. It never decodes executable callbacks from configuration.

Before changing capacity or provisioning, the actor requires the reviewed native
feature source protocol and an exact accepted-main prepared controller inventory.
It obtains its own guard and separately prompts for
`authenticate-native-allocation`. The native prompt explicitly authorizes one new
allocation despite unconfirmed original cleanup. The process-local lease binds
that exact allocation, source, configuration and provisioning plan. Authentication
for ordinary restoration does not cover this purpose.

The original allocation actor sets umask 077 before helper/guard/provisioning
writes. Generated native file modes remain measured and pinned by the reviewed
stock VM owner; the mask never substitutes for physical file verification.

Provisioning requires a private, independently acquired staging-only arm64 raw
image compressed with zstd. The pinned actual decoder streams and hashes the
compressed bytes, independently counts expansion with a 16 GiB ceiling and
128 MiB window limit, and verifies original file identity before and after. It
does not write an expanded scratch image. Unknown formats, xz without a qualified
decoder, inconsistent expansion counts or changed image bytes refuse. VM init,
the 16 GiB disk bound, 4 GiB memory, two CPUs, source witness 64 MiB scratch,
compressed input and controller/scratch commitments must all fit the accepted
resource policy with at least 20 GiB free. No evidence is removed to make space.

The original actor retains the actual measured VM plan and original process
capabilities. It starts once, verifies actual boot, supervisor/helper births,
disk/EFI/configuration/control identities and guest endpoint, then awaits the
original app readiness fence. The exact app is recorded before releasing the new
guard. A synchronous handoff installs the original custodian lifetime while that
guard remains held. The completed record retains the independent allocation
proof and explicitly does not claim original native cleanup.

Initial purpose authentication and the bounded source-acceptance witness only
admit that first allocation/start. After the verified handoff, original resources,
check and drain depend on the same live registered parent, original app/custodian
and immutable reviewed source/VM facts. Their availability does not expire with
the consumed admission authorization. Another start, lease or handoff cannot be
replayed.

Final normal retirement first closes the actual native host and runtimes. Only
the source-owned `beforeRetirementReceipt` callback then exposes the original
bounded retirement lifetime. The actor retains its independent registered parent
and source fence, normally stops its own VM and positively confirms the original
job/process/backing/endpoint closure before allowing a custodian retirement
receipt. Unknown outcomes preserve uncertainty; the new disk/EFI remain retained
and accounted. This protocol grants no backing deletion and no old archive cleanup.

This branch has not been applied on the host. Live recovery, helper enrollment,
fresh private provider/TLS configuration, actual stock image provenance, native
device authentication, first boot and original model-account enrollment still
require independently reviewed accepted source and original physical validation.
All source tests described in the changes are offline and make no model calls.
The entry refuses when the actual native feature/enrollment/model-call source
implementation is unavailable. A conditional native factory cannot by itself
qualify an account, a Luna call or per-request model enforcement.

The existing owned router currently supports check/drain, and ordinary deploy
does not update the native custodian. An app-only source update must retain the
same original VM/custodian through a positively drained original app-child
replacement, exact accepted-source admission, compatible retained native protocol
and new actual child identity. It must report retained runtime source separately
from the updated app source. Changes to retained custodian, provider, inference
or VM runtime code require a separately reviewed runtime transition. Merely
reopening a plan, changing topology JSON, starting another VM or retaining a new
16 GiB disk on every revision is not an implemented source-update path.

A cancellation before any native preparation attempt may be acknowledged only
by the still-live original new launcher. The physical inspector captures the
complete private fresh allocation tree, requires empty fresh HOME/workspace,
excludes an init attempt, VM plan/plist/configuration or guard socket, and
positively observes the exact native job absent. Source, completed archive and
sole unchanged original row must also remain independently current. The actor
fsyncs a separate refusal receipt before releasing only its matching new guard;
the receipt explicitly grants no capacity release, cleanup or replay. Any
preparation attempt or unknown observation preserves that guard and evidence.

Before an ordinary owner is drained, run the separate read-only source/config
preflight from its exact prepared accepted release:

```sh
node scripts/preflight-contained-native-staging.mjs check --bootstrap PRIVATE_BOOTSTRAP_PATH --expected-bootstrap EXACT_BOOTSTRAP_SHA256
```

The command derives its prepared source from its own executable path. Its actual
private inspection stays in a process-local branded token; reopened JSON cannot
supply source loaders or authority. It checks the separate native model,
conditional feature and independent custodian lifetime source protocols without
registering a job, authenticating, opening a guard, creating a host or mutating a
VM. A missing implementation therefore refuses before ordinary shutdown. A
successful observation still grants no installation or native authority.

The source-owned custodian now exposes a separate actual host/PID lifetime to
its original launcher. It survives an app-channel gap and permanently closes on
native retirement or loss of host custody. Features additionally require the
latest original app-channel fence, so the retained VM resource observer does not
admit feature work while an app is quiesced. The actor wires pre-mutation
cancellation to the physical inspector and retains its guard after any native
preparation attempt, claim or uncertain verification.
