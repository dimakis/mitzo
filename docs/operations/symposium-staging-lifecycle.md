# Canonical staging lifecycle boundary

Canonical Symposium staging uses one persistent environment at
`http://mitzo-staging.localhost:3190`, one `com.mitzo.staging` service and the private
root `~/.local/share/mitzo-staging`. Its registry has capacity exactly one. Do not
create per-conversation backends, custodians, trial labels or another registry.
Retained October trials are historical evidence; their generic preparation APIs
are not authorization to create additional live stages. Production is excluded.

## What the operator cut provides

The static foundation validates private release/configuration inputs and original
parent/app metadata. This dependent operator cut provides private service
preparation, an exact-commit ordinary-to-owned transition and owned check/drain
entrypoints. Preparation only emits a manually started plist; it does not install
or launch it. Transition apply requires a separately qualified controller at
fresh accepted main and a separately reviewed target source/build/configuration.

The registered target launcher, registry writer, original process-local callbacks,
gateway custody and canonical no-force custodian exit are deliberately absent
from this cut. The operator commands cannot supply or reconstruct those owners.
Do not use a missing launcher as a reason to start main's ordinary custodian or
borrow an old trial, registration, native operation or production configuration.
The target lifecycle source must receive its own complete review and qualification.

## Required target lifecycle contract

The reviewed target must reserve the fixed private capacity-one registry slot
before claiming its exclusive `launch.intent` or bootstrapping native resources.
Its same original parent must retain the registry recording closure and native
owners. The live callback records the original parent/app process birth,
relationship, source/build/configuration and instance/generation identities.
There is no exec/restart transfer or receipt-based adoption of that closure.

Active, uncertain, retiring and unconfirmed-retirement states retain the slot.
Process exit, an empty listener inventory, a timer or a model response cannot
release it. The original owner writes its matching native retirement receipt only
after exact cleanup and gateway closure; its original closure records retirement.
No database edits, forced retirement, launch-intent deletion, force escalation,
parallel replacement or automatic rollback can substitute for that proof.

Until this target contract is implemented, reviewed and physically qualified,
the ordinary stage remains selected. Do not run the transition apply command,
install the prepared plist, start a VM/custodian or perform provider enrollment
as part of this operator source cut. The existing VM, private state, workspaces,
HOME, settings and retained evidence remain preserved.

## Original-owner check and retirement

Owned check verifies the selected original release, original parent/app and3190
listener, the private capacity-one registry and production listener exclusions.
Owned drain requires exact source, original instance and controller epoch. Only
an explicit apply requests SIGTERM through the original verified staging job,
under the same exclusive deployment lock as ordinary updates and transition.

Success requires absent original processes/listener and a matching original
native retirement receipt and retired registry state after the requested drain.
Missing custody, unclear process identity or uncertain retirement preserves the
lock, registry, intent and evidence. The VM remains running until native
retirement is confirmed. There is no startup or replacement path in owned drain.

These are operator checks and control effects, not native capabilities or physical
acceptance. Provider sign-in, supported Luna discovery and bounded real acceptance
remain separate. Announce the exact verified Luna model and charged account before
any real model test; none is performed by this source cut.
