# Native staging profile admission preparation

This source phase prepares actual native Vertex draft/candidate admission. It does not implement a native
feature runner, enroll providers, allocate a new environment, release uncertain
capacity or prove a live run. Canonical staging remains separately fenced until
accepted recovery, original archive, fresh purpose authorization and independently
reviewed VM/config/provider enrollment are complete.

## Original Vertex path

The native Claude executor already uses the original gateway's same-process
Vertex provider receipt. Its concrete supported selection is region `global`,
model `claude-haiku-4-5@20251001`, exact enrolled principal/account/project, and
one pinned provider ID/workspace. It has no Luna route. A live test requires
Dimitri's explicit approval of that exact alternative after the fresh staging
principal/account/project are known. This source does not approve that exception.
Neither production provider metadata nor credentials may fill missing staging
inputs.

The actual app's session-create composition now provides a Vertex-only callback
that reads the installed original host's attestation, verifies its existing
physical/native runtime gate, and checks its real selected Vertex route against
the retained receipt. The callback is constructor wiring, not request data. A
router without that capability refuses Vertex before allocating a draft. A draft
contains saved guidance and selected account/model; it grants no execution,
membership, native process or artifact admission.

The original owned-host candidate and current-mapping wrappers derive their
provider scope from the current draft and AccountProfiles. They admit homogeneous
OpenAI API or Claude Vertex seats sharing one exact provider instance; no caller
provider, extra role, mixed route or alternate model can widen that scope.
Personal ChatGPT stays on its distinct private native-auth admission path.
Future unsupported providers remain refused.

The existing owned evidence collector verifies the actual original gateway,
reviewed runtime image/build/native artifacts, provider public profile and artifact
volume. Vertex candidate verification additionally captures the original gateway's
retained receipt and matches principal presence, account, project, region, model,
provider ID and workspace against every selected seat. After awaiting that check,
the collector rereads the original artifact mapping before returning authority.
Receipt loss or changed source/profile/draft/mapping refuses admission. The
existing local B20/native variants that only permit OpenAI are not broadened;
Vertex still requires the reviewed Claude runtime capability.

## Remaining native feature work

A working native feature owner must be constructed in the original custodian with
its actual host, grants, attempt registry, runtime getter and controlled targets.
It needs a host-issued bounded fixture source/session/grant, exact native
claim/delivery/provenance events, original `confirmStopped()` acknowledgments and
owned sandbox retirement receipts. Retained session artifact volumes must be
accounted for explicitly. No controller end, idle state, abort, suspend, process
lookup or persisted receipt recreates physical cleanup authority.

Codex automatic compaction remains unqualified for this suite. The inspected
OpenShell REST policy constrains method/path and credential/policy generations;
the installed native profiles currently have no original-owner request-model
predicate or finite inference-request counter. Its built-in middleware registers
regex redaction/observation rather than a JSON model/account budget gate. A
request-path restriction can reject a distinct `/compact` endpoint but cannot
prove the model or count hidden same-endpoint calls. Native policy/runtime source
qualification would be required for that enforcement; this phase adds no proxy or
native build and never guesses a Codex disable-compaction setting.

All validation here is offline. Fixture provider strings, mocked collectors and
native receipt comparisons are regression tests, never live enrollment evidence.
The full personal/API/Vertex/future-profile feature replica remains pending.
