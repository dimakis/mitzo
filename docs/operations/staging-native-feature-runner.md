# Conditional original native text/Read runner

This source implements the original-owner factory, fixture/grant/native executor,
claim/event collector and physical retirement path for `profile-tools-v1`.
It is **not live-proven**, does not complete full feature/profile parity, and
cannot currently plan or dispatch a native model call. The separately qualified
original gateway HTTP account/model/auxiliary/two-request authority is missing.
`captureQualifiedStagingNativeModelAuthority` refuses before any fixture or
native launch. The launcher must require a separate
`STAGING_NATIVE_MODEL_ENFORCEMENT_PROTOCOL_VERSION === 1` before device
authorization or allocation; that export is intentionally absent. Factory
protocol 1 alone does not authorize a native allocation.

`runSymposiumCustodian` constructs the feature owner after its actual
`bootstrapConfiguredSymposiumHost` and `installSymposiumProductionHost` calls.
It retains that exact host, gateway, app EventStore, host grants, native runtime
and attempt registry. Its controller-current closure becomes available only
when the original awaited `beforeControllerReady` fence completes. The fresh
launcher supplies accepted source roots, original owner/source assertions, and
its actual original VM owner's zero-argument `observeResources` capability.
Allocation authentication does not prove provider enrollment. Provider
capabilities are minted inside the original host's actual factories.

## Actual bounded execution path

Once the independently reviewed gateway authority exists, the owner resolves
only the requested current profile and chooses an explicitly supported Luna.
The exact charged account must be returned by the original authenticated model
policy capability; a profile label or newly created provider alone cannot prove
billing identity. The exact model/account, all dispatch scope, accepted source, original owner,
profile/enrollment revisions, runner/suite digests and bounds enter the immutable
plan/hash. A single-model Vertex catalog can identify an exact candidate for
exception review; only the authenticated original gateway policy may supply the
approval. Caller model IDs, approval IDs and result Booleans grant nothing.

The actual accepted singleton queue guard runs before fixture, admission,
dispatch and finalization. The real private custodian HTTP request lifetime is
retained and rechecked, including operator revocation/expiry. Only one foreground
runner can be active. The entire effect budget is 180 seconds; effects refuse
when it expires. A failed or timed-out runner remains owned and fenced.

The executor creates one actual v2 draft and a fresh original host artifact
volume. A fixed Python helper exclusively writes a 64-character nonce into
`nonce.txt`; it uses the existing owned Podman command path, pinned workload
image/user, no network, read-only root, no capabilities, eight PIDs, 32 MiB,
one CPU and a 20-second bound. Its exact terminal container ID is journaled
before further checks. Positive start output and exact removal acknowledgement
are required. Ambiguity retains the original name/ID and never triggers forced
removal or adoption after restart.

The original host collects the actual session-scoped physical/provider candidate.
The actual app HostGrants activate a read-only reviewer, and the existing native
runtime admits its membership generation. Before any native manager/startup, an
awaited original authority prepares a provisional deny-all inference guard for
the exact original workspace/sandbox name/session/claim. Actual native
CreateSandbox/GetSandboxConfig must consume that opaque original guard and
install denial before process startup; a caller flag or bare ID does not grant
inference. After the actual sandbox ID/current supervisor connection exists, the
same original guard can issue the exact bounded model budget before a native
turn. Missing native RPC transport, issuer or guard consumption remains a refusal. The fixed delivery requests only the fixture Read and its text.
Codex's actual read-only configuration disables shell/exec, so this source adds
one fixed Read through the existing native dynamic-tool bridge. Its original
owner reads only the immutable nonce volume through a read-only, no-network
32 MiB/eight-PID helper, checks mode/size/link/hash, and positively removes the
exact helper before returning the real tool result. The original accepted
runtime/claim must qualify that tool; cached nonce data or result flags cannot.
A missing/ambiguous Read receipt blocks fixture retirement. Claude Vertex uses
its actual native built-in Read and receives no additional host tools.
It uses the ordinary native Codex/Claude factories and their current source
admission; it does not substitute a local provider or another runtime.

The collector reads the app's delivered recipient attempt, exact original native
accepted thread/turn and completed observation, account/model binding,
provenance, one successful Read of the nonce file, and streamed nonce text.
It refuses conflicting, mixed, stale, incomplete or oversized facts (at most
256 events and 64 KiB). It proves neither model enforcement nor cleanup itself.
Actual checked HTTP requests and positive grant revocation must come from the
separately qualified original gateway, with the same account/model/claim/sandbox,
no more than two inference requests, and disabled auxiliary scope. All failed
attempts, retries, compaction and helper inference routes must be covered.

Cleanup awaits the original controlled target's positive controller stop
acknowledgement; durable recovery/confirmed rows cannot mint this receipt.
The actual Codex, personal ChatGPT and Claude constructors pass the original
staging queue/lifetime assertion into the original attempt registry's launch.
It checks before launch and before/after the retained process's positive stop
acknowledgement. Lost authority keeps the claim uncertain and cannot mint an
original stop receipt; a rejected confirmation is retained rather than replayed.
The original manager's ensure/inspect/stop/delete methods check the same private
queue reservation before and after each awaited staging effect. The wrapper
delegates to that retained manager and preserves missing methods; it supplies no
runtime replacement or successful observations. Queue loss after an effect
prevents a positive cleanup result and retains uncertainty for reconciliation.
The actual original sandbox owner requires its retained terminal creation,
positive physical stop and deletion, and artifact lease release. Reconstructed
owners, disappeared resources, SDK abort, idle, suspension and transcript end
cannot mint these receipts. Only after those facts and zero remaining original
claims/leases may the retained fixture capability remove its exact labeled
volume and verify absence after the acknowledged delete. Journals retain
uncertainty and cannot recreate live verification authority. Full receipts stay
in the original owner's memory; the queue receives a bounded hash/reference.

The original host tracks the entire feature operation through its own drain
lifecycle. Before the whole custodian retirement receipt, the fresh launcher's
separate awaited post-host hook must invoke the original VM owner's normal
`stopOnce` and physically positive `confirmStopped`. The hook uses the retained
parent/process/source fence after gateway IPC closes. Disk backing retention is
accounted separately; neither this runner nor a retirement JSON removes it.

`store:false`, `stream:true`, and omit unsupported fields including
`max_output_tokens`, `max_tool_calls`, `previous_response_id` and hosted MCP.
See the official [model/inference guide](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference),

and fresh authorization; it is not a conversion of an existing private ChatGPT
provider or a borrowed Codex token. It remains a source/enrollment dependency.

## Authenticated existing IPC and resources

The finite existing custodian protocol adds only enrollment, plan, run, receipt
and resources operations. The canonical controller forwards them to its actual
retained owner before any controller-local feature route. There is no install,
configuration, model, arbitrary prompt or host-command endpoint. Aliased or
unsupported feature namespaces are fenced. Missing owner/authority stays 503/409.

`GET /api/staging/features/resources` returns
`{version:1, sourceCommit, ownerInstance, resources}` from the actual original
launcher VM callback, within the original authenticated IPC lifetime. The
canonical client `observeResources(sourceCommit, ownerInstance)` checks the
finite envelope and exact source/owner plus the native 4096 MiB/two-CPU facts.
JSON observations do not themselves grant native capacity. The canonical
origin, accepted source, original owner and constructor capability still require
independent qualification. Generic Mac observation must continue refusing
unknown allocations instead of reporting zero VMs or accepting JSON overrides.

This bounded suite covers text and Read only. Permission, reconnect,
cancellation, queue, MCP, hooks, images, compaction, subagents, integrations,
phone and other feature families still need their actual bounded suites and
original cleanup receipts before full replica acceptance. No live call, new
native resource, enrollment or production action was performed for this change.
