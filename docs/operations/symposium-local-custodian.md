# Local Symposium custodian

The optional `npm run start:symposium-custodian` entry point runs the existing owned host and Symposium runtime owners in one retained process. It supervises the ordinary web app as a replaceable child. Build first with `npm run build:server`. Supply the existing private `MITZO_SYMPOSIUM_OWNED_HOST_CONFIG` and explicit app authentication, repository and listener settings to the custodian. This is a fresh-launch path: it does not attach to an existing gateway, import old capabilities, or adopt an orphaned fixture.

## Ownership and authorization

The retained process owns the original gateway child and issuer, personal/provider authentication, native cancellation handles, terminal creation receipts, artifact owners, single Symposium orchestrator per session, and existing SQLite ledgers. The app receives no provider credential values or management environment. Its explicit environment allowlist preserves staging isolation, disables dotenv reload, and omits the owned-host configuration and native-attempt bootstrap directory.

The app and custodian communicate through the OS-created inherited IPC channel of the exact supervised child. The protocol enumerates semantic operations; it accepts no arbitrary URL/verb, command, host configuration, reflection method or callback. Existing Express routers validate the actual operations inside the retained process. The app validates the browser JWT and recent-CSRF capability before forwarding a request-scoped JTI/expiry assertion on this private channel. Neither JWT nor passphrase nor CSRF value is forwarded. Expiry, logout and epoch loss invalidate outstanding authority. A public request cannot construct the request-object authority used by the retained router.

Each child receives one exclusive controller epoch. Duplicate active controllers and stale epochs are rejected. App loss, channel failure or a missed heartbeat fences new work. The custodian records suspension of retained active memberships, including the anchor, using the existing membership ledger. Ordinary operator actions still cannot revoke the anchor. Exact native, seat and creation cleanup must complete before another child is admitted; unknown effects retain their original claims and prevent replacement. Completed personal/provider authentication remains in the original owner and does not require another provider sign-in.

Replacement requires fresh app-operator authorization and an explicit normal seat restore/admission. It never silently resumes a model turn or restores browser publication approvals. Only sessions created by this custodian may use its host; persisted sessions, IDs and Ready inventory cannot reconstruct custody. Draft creation interrupted during artifact initialization stays draft and cannot become active merely because a new child starts.

## Recovery and compatibility

The app retains ordinary session recovery. In controller mode it excludes typed Symposium sessions and historical rows containing any Symposium config from generic session, execution and send-command recovery. Import-time Symposium delivery recovery is disabled in both split processes. The shared Codex conversation ledger has an immutable `owner_kind` discriminator: controller recovery touches only positively owned ordinary commands. Legacy NULL-owner rows remain readable but cannot be adopted for execution in split mode. Ordinary unsplit startup keeps its prior recovery behavior. Plan deployment around fresh fixtures and legacy ownership; do not point this entry point at a retained historical fixture and call that recovery.

The existing artifact initialization, source import, sealing, export and generation implementations remain with the retained host. This increment forwards creation/source operations, Director operations, profiles, personal setup and catalog/admission diagnostics. It deliberately leaves publication registration and browser approval bridging unavailable in custodian mode; direct-app publication remains unchanged. Native trusted review admission still requires the independently missing supported hard-budget and final-accounting contract. No native pins or upstream contracts change here.

## Diagnostics and limits

Authenticated `GET /api/symposium/custody` returns `instanceId`, `epoch`, `custodianPid`, `controllerPid`, `state: active` and `scope: fresh-retained-sessions`. This is an observation, not a transferable capability. An acceptance harness must compare the PID to its original launcher handle, remember the random instance identity, and require that same identity plus a higher epoch after app replacement. PID reuse, a response copied from disk, or a fresh custodian cannot authorize adoption.

Custodian death remains unsupported: affected resources are quarantined. A drain timeout is not successful shutdown. Heartbeat detection and cleanup use the retained Node event loop; existing synchronous physical verification can delay detection until its bounded subprocess calls return. This is not a real-time kill guarantee or a native inference budget. Failed cleanup retains the owner and stores for diagnosis, stops automatic controller replacement, and reports quarantine.

Offline tests cover actual JWT/recent authorization, logout after an HTTP response, stale epochs, real child SIGKILL/replacement with retained SQLite, uncertain cleanup, atomic anchor suspension, pending creation-recovery rollback, a deferred artifact-initialization race, immutable Codex ownership and scoped startup recovery. These tests use injected physical effects; they are not evidence of a live provider recall or a real workload crash drill. No model calls are required by the tests.
