# Unpersisted Codex replacement threads

A native `thread/start` response does not prove its rollout is persisted. Ordinary OpenShell tool-surface replacements stay pending in the live conversation until an exact `turn/start` acknowledgment. The accepted turn transaction promotes the new generation and then updates ordinary runtime lifecycle ownership. Closing before dispatch leaves the canonical parent unchanged; reopening safely prepares another replacement from completed host history.

A durable `codex_pending_thread_dispatches` row is written immediately before sending `turn/start`. If transport fails after dispatch or its ACK is lost, reopening blocks: the outcome is unknown. User queue acknowledgment alone cannot clear this fence. Only a standard JSON-RPC invalid-request rejection with numeric code `-32600`, `-32601` or `-32602`, categorized `invalid_request` and with no conflicting turn notification, can clear the exact dispatch fence while preserving the command failure/tombstone. Authentication, rate-limit, context-limit and other server or transport failures retain it. Recovery of an unknown dispatch needs separate reviewed native provider evidence and command-ambiguity resolution; the legacy utility below must refuse it. Initial fresh threads have the same ACK boundary, with a nullable parent and provisional lifecycle ownership until accepted.

Native acceptance is retained in `codex_thread_acceptances` atomically with thread promotion. A failed lifecycle or artifact ownership observer leaves `ownership_pending` set and preserves the accepted command as recovery work rather than a failed dispatch. Reopening validates the exact native thread, binding and generation before retrying ownership registration; this does not acknowledge or replay interrupted commands. Conflicting native terminal outcomes set `terminal_conflict`, preserve ambiguity and block automatic ownership repair until separate reviewed inspection resolves the contradiction.

## Reviewed legacy quarantine

`scripts/quarantine-legacy-thread.mjs` is an operator-only, default-dry-run tool for the one proven legacy generation selected in its immutable `LEGACY_SCOPE`. It is not a general missing-thread repair command. The scope pins the conversation, ghost/parent IDs, creation cut, account binding hash, source/candidate physical IDs, and both historical command IDs/sequences/input hashes. It blocks any changed account, accepted dispatch, ambiguity, queued target input, existing native child, unknown scope, enabled lifecycle or race.

The tool verifies fresh whole runtime contracts and actual candidate image, then reads only native first-record IDs/counts and SQLite thread counts in the already-owned source/candidate. It also reads the authoritative protocol database: both historical `user_message` events must predate the orphan cut; no post-cut sends/admissions/provider attempts/provider events are allowed. Prompt bodies remain in memory for fingerprints and are never printed. All command, tool and adoption rows are fingerprinted to detect concurrent changes.

Only after the server is already stopped and user sends/automation are explicitly held may an operator run this accepted detached build. The tool does not stop/start the server or resume a provider. It requires the LaunchAgent absent, both3100/3101 listeners absent, no native app-server in either scoped runtime, private physical environment/snapshot files and existing owned physical databases without group/world write permissions. Existing0644 databases are accepted without chmod. The clean detached utility release must match canonical origin and its fresh remote main SHA. Apply additionally holds the standard deployment lock. Maintain the external hold throughout; a server-off snapshot is not a universal provider admission fence.

The CLI validates every option before reading operational files, checking Git/services, opening databases or running native probes. `--apply` and `--snapshot-out` are incompatible; unknown/duplicate flags, missing values and missing required scope arguments fail with a fixed diagnostic and no operation.

First collect a dry-run snapshot with explicit `--accepted-head`, `--env`, `--database`, `--events-database`, `--conversation`, `--confirmed-held-inputs`, and `--snapshot-out`. Privately review its fingerprint against the previously authorized exact target. Then repeat with `--expected <private snapshot>` and `--apply`. The CLI has no alternate-scope override. These commands are preparation instructions, not authorization to operate on a different session or to shut down an active service.

The synchronous SQLite CAS sets only `tool_surface_revision=NULL` and appends `codex_unpersisted_thread_quarantines`. It preserves the ghost gen1 as canonical/audited history, retained rollover context, parent generation0, every command/FIFO/receipt, committed migration13 and its immutable checkpoint. It never rewinds or reuses a generation ID. Normal fixed-code initialization sees the stale tool surface and starts a fresh pending child without resuming the absent ghost; only a matching accepted turn appends generation2. Lifecycle-enabled legacy repair is blocked rather than inventing a checkpoint identity.

Failure aborts without changing the mapping or queues. A repeated apply refuses the existing marker. The private backup and all-provider maintenance coordination belong to the external accepted activation procedure; this utility performs no service action, sandbox cleanup or model call.
