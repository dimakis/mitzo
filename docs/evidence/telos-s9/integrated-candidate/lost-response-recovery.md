# Actual committed-response loss and explicit browser recovery

`lost-response-browser.contract.ts` uses the same real app/auth/SSE/outbox/native
owners as the first non-Git journey. The actual browser reviews and opens its
advisor with retained origin/material context. Provider/account RPC and declared
external integrations remain fake; the private canonical read uses bundled3077
source and the isolated PyYAML-only runtime.

The browser's first POST is forwarded to the actual owned API with `route.fetch`.
Only after its actual202 consumed/dispatched acknowledgement is read does the
test abort that HTTP response. No owned API is fulfilled or replaced. The real
native owner has admitted exactly one turn. The test verifies the actual reviewed
per-command localStorage entry is uncertain, adds a newer unsent draft, finalizes
the fake provider reply and fully reloads the document.

Reload restores the draft and history and reattaches the original client without
resending. The operator opens the existing settings and clicks **Recover original
Local command**. The second POST is byte-equivalent as a JSON request to the first;
the actual owner returns consumed/dispatchedfalse. Native launch/turn, original
workspace/inode, selected source/context/material bytes and exactly one retained
user message remain unchanged. No execution task or unrelated initial command is
created. The newer unsent draft remains intact after recovery.

Two early diagnostics inspected incorrect storage namespaces: the generic outbox
key, then sessionStorage. The actual client uses its reviewed per-command
localStorage adapter. These are retained fixture failures, not product defects.
The corrected working case passes1/0skips in6.97s; exact signed-source execution
is retained separately after freezing. No source expectation or producer fence
was weakened.

This proves consumed-response loss, document recreation and explicit exact replay
for this non-Git candidate path. It does not prove full server/native process
restart, cold recovery, repository recovery, offscreen late results, revocation,
full shared-owner coexistence, accepted main, full UX or a live runtime. The
required CI runner selects this case independently and keeps its own captures.
