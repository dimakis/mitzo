### Rebase risk

`chat.ts` was modified by #280 (Phase 2 isolation) which just merged. The `startChat()` function gained `buildOnDemandCreate()` and modified the resume discovery block. #282 wraps `startChat()` in a span — expect conflicts in `chat.ts` around the function body.

### Codex review findings (6 total, all unfixed)

1. **BUG — turn span not activated** (`query-loop.ts:602`): Turn span is created but never set as active context via `context.with()`. Tool child spans parent to the session span instead of the turn span. Fix: wrap the tool span creation inside `context.with(trace.setSpan(context.active(), turnSpan), () => {...})`.

2. **BUG — interruptChat not awaited** (`index.ts:696`): `interruptChat()` is async but called inside synchronous `withSpan` without `await`. Promise errors are silently lost and span ends before interrupt completes. Fix: use `withSpanAsync` instead.

3. **BUG — swallowed exception in catch** (`ws-handler-v2.ts:434`): Inner catch records exception via `span.recordException()` but doesn't re-throw. `withSpan` then sets status to OK. Span shows both an exception and OK status. Fix: re-throw after recording, or set span status to ERROR explicitly.

4. **STYLE — variable declaration ordering** (`query-loop.ts:174`): Minor readability — `goalCreationPromise` declaration separated from its logical group by new tracking variables.

5. **REGRESSION — connSpan removed** (`index.ts:443`): V1 connection-level span removed without replacement. Connection-level tracing lost. Consider whether this matters (v1 is legacy).

6. **REGRESSION — session-not-found no longer ERROR** (`ws-handler-v2.ts:246`): Old code set span status to ERROR for missing sessions, new code returns early with OK. If dashboards alert on ERROR spans, this is a silent behavior change.

### Recommended approach

1. `git checkout feat/otel-context-propagation && git rebase main` — resolve conflicts in `chat.ts`
2. Address the 3 bugs (turn span activation, async interrupt, swallowed exception)
3. Assess the 2 regressions (connSpan removal, error status change) — probably acceptable
4. Run full test suite, push, wait for CI + review
5. Land with `/land-pr 282`
