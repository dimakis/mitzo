# Ordinary Local Claude source status

This is an offline source checkpoint for the existing ordinary session picker and generic runtime endpoints. It does not qualify a deployed runtime or canonical staging. No provider request, credential enrollment, browser run, SDK sandbox process probe, or staging deployment was performed.

The explicitly enabled Local route projects enrolled `anthropic-vertex` accounts with the `claude-sdk` harness. OpenShell remains the picker default. OpenShell Vertex is unavailable. Gemini adoption is a separate NativeResponses change. Public inventory and session metadata expose opaque account, target and profile revisions, models and bounded reasons; ADC paths and custody remain private in the existing session store.

First commands and followups use the existing repository claim, ordinary admission, send receipt and execution ledgers. Accepted FIFO entries retain their original model, effort, text and attachments. New native SDK queries are opened only after the preceding terminal result and resume the original SDK UUID and working directory. The existing `resolveThinking` and `resolveClaudeEffort` functions supply query options; a thinking budget setter is not treated as adaptive effort control. Explicit cold continuation verifies the original SDK history and restores only positively acknowledged, never dispatched queue entries. Reserved or uncertain dispatches are refused rather than replayed.

The original signed operator, persistent revocation authority, exact profile and workspace authority are checked before effects. ADC custody pins canonical physical file identity, hash, project and region. Missing files, replacement, refreshed file content and changed configuration refuse continuation; credential renewal adoption is not implemented. Only supported authorized-user and service-account ADC shapes are accepted. Ambient keys and Google billing/project overrides, alternate providers, external-account configuration and redirected Google token authority are refused. The selected ADC remains readable by the SDK, while the existing whole-process SDK boundary denies writes to selected credential and runtime configuration authority.

Compatible published plain profiles and canonical plain builtin profiles use the existing Library namespace authority. Context recipes, packs and incompatible providers remain unavailable. The owned SDK exposes the existing profile MCP tools and shared web helper; configured connection helpers are not enrolled for this route. Native SDK hooks and permission decisions recheck authority, and retired query hooks refuse effects. Offline regressions verify canonical builtin admission and that retired native query hook and permission callbacks refuse without affecting the successor. Whole-process sandbox enforcement and native builtin execution remain unqualified.

Offline checks currently cover actual generic REST first, queued future and cold SDK commands with a fake SDK; same-thread model and effort options; custody persistence and strict credential replacement refusal; durable admission identity and public custody omission; FIFO settings and revoked control acknowledgements. The original isolated checkpoint passed 40 tests across seven files; integration adds actual Stop, cold acknowledged FIFO, original/foreign/revoked queue custody, and overlapping retired-approval regressions. Final source-only TypeScript verification and focused source/test ESLint passed. Additional fixtures verify exact original native history lookup, missing/foreign history refusal and retired hook/permission refusal.

The canonical shared queue-control guard now owns Claude cold cancellation. Final async and sync authority callbacks reach profile effects after waits and existing publishing/web helper paths; those latter helpers are not exposed on this route. Cold availability is a bounded source projection; dispatch performs native history and credential checks. Interrupted execution without a native terminal result remains explicitly unconfirmed and cannot cold replay. Hosted browser checks, OS-boundary qualification, independent configuration review and canonical staging qualification remain outstanding.

Terminal query replacement waits for the exact spawned process to emit close, then rechecks the original authority before replacement. Exit flags alone do not prove closure. A bounded timeout or cancelled wait refuses dispatch and retains queued commands, history and workspace; the barrier does not force-kill a process. Fake process tests cover delayed closure, timeout and retired callbacks. Cold physical orphan custody and live SDK process behavior remain unqualified.

## Local startup and restore regression, 22 October 2026

The deployed owned Local Vertex route accepted and answered its first command,
but SDK startup emitted that command again with the same identity and internal
repository setup context. Reconnect history rejected the duplicate identity with
HTTP 500. The original conversation and its saved reply remained in the event
store. The SDK launch also omitted `--replay-user-messages`, while the FIFO owner
required that native acknowledgement to correlate a terminal result. Missing
acknowledgement therefore aborted the owner after the first answer and left its
execution unsettled.

Owned queries now request native stdin acknowledgements on every query,
including resumed queries, while preserving other SDK arguments. Controller
accepted prompts are not re-emitted or overwritten by native startup. New owned
session metadata retains public user text rather than internal setup context.
History and bounded reconnect project the known old startup duplicate only when
the original stored Vertex custody and send receipt identify the first command,
the accepted user event matches its exact text, and the duplicate matches the
stored repository envelope. Stored events remain unchanged; foreign, attributed,
and conflicting duplicates still fail closed. The immutable reconnect cursor is
preserved.

The route has native SDK tools under existing permissions, even though it omits
configured integration MCPs. Runtime guidance now directs Google Workspace tasks
to inspect local `gws` availability and help before claiming access is missing.
CLI installation does not prove authentication; no Google read or credential
change was performed for this fix. Connection tools are still not enrolled on
this route.

Offline regressions cover launch arguments, query replacement, prompt acceptance,
HTTP history and bounded reconnect, and rejected conflicting attribution. A
read-only projection of the actual retained affected events reproduced the old
failure and restored the original prompt and reply with the fix. Tests use fake
providers and local records, with no real model calls. This change does not
settle old unconfirmed executions, restart their native processes, or replay a
command. A conversation whose old execution remains running needs separately
verified custody recovery before cold continuation. No production deployment or
staging operation was performed.
