# Ordinary runtime picker route scope

The existing picker exposes exactly two environment choices: OpenShell and Local Mac. OpenShell remains the initial choice, including when unavailable. Native target identifiers and software are derived from the trusted account, location, harness and target tuple. Duplicate or mismatched targets and ambiguous routes do not create additional environment choices or silently choose the first route.

An explicit account or environment edit may resolve the new native target before admission. It retains model, thinking, text, images and context. A retained account provider or configuration revision mismatch requires explicit Account re-selection; refresh and capability review cannot replace it. Model and thinking catalogs come from the selected native route, with eligibility checked against its published profile snapshot. Unsupported combinations keep the account and unavailable model visible with a reason. Both chat pages use this same projection.

Admitted conversations derive software from their immutable binding. Future model and thinking choices remain within that route. New session elsewhere copies the original opaque account and agent intent into an independent draft with no native target or repository preparation; it does not move the existing conversation.

Offline page regressions cover API billing through OpenShell Codex, Local Responses, explicit Local Claude and unavailable Vertex OpenShell. They verify two environment choices, truthful software, invalid model and thinking retention, unchanged persisted draft attachments/context, and no send or billing substitution. Hook and route regressions cover exact account reference drift, target/harness mismatch, ambiguous routes and route-scoped catalogs. Browser fixture selectors were updated for the two environment values; no local browser or backend was started.

A legacy retained account ID without its public provider/configuration reference is unconfirmed identity, not a fresh default. Loading capabilities, environment edits and capability review cannot adopt the current tuple for it. An Account choice made before trusted capabilities arrive remains unconfirmed too. The existing Account field shows a disabled Confirm account placeholder for an unconfirmed current candidate. Selecting the real account once explicitly confirms its trusted tuple while preserving model, thinking and draft contents; capability refresh cannot confirm it automatically. Pristine drafts with no account still resolve the ordinary OpenShell default target without additional setup.
