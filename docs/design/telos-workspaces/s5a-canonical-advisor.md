# S5a canonical advisor persistence

Advisor child creation must use the actual MGMT schema. The accepted writer omitted
required `first_seen`/`last_seen` values, so a reviewed child failed before its
source and receipt could commit. It also omitted the canonical creation-history
entry. The fix writes all four creation timestamps together and records exactly
one `NULL → active` history row inside the existing immediate work transaction.
Classification, borrowed-connection source/material retention and the final receipt
remain in that same transaction. Refinement preserves observation/creation dates,
priority, criteria, category tail, provenance and unrelated hints.

The current fixture directory `server/__tests__/fixtures/telos-canonical-3077b7b4`
was generated by actual accepted MGMT `3077b7b4dcdf0ef097062794b2ab93d33c1d89ad`,
including a fresh database and migration from historical `8d667f1cf9cddbd756d916bfcf50b2a936f7daff`.
Its manifest records owner file hashes, complete DDL hashes, upgrade preservation
and default-database fencing. Regenerate with `scripts/prepare-telos-canonical-fixtures.py`
using those pinned revisions. The original b4ad fixture directory remains historical
evidence. Advisor tests now use the real current DDL instead of adding a test-only
categories column.

The regressions exercise child/refine on both schemas, preserve all original row
fields through the real mounted HTTP routes and typed client, reopen real stores,
replay exact identities and reject changed input. Item/source/receipt fault probes
run on both schemas and must reach their named injected exception before rollback
can count. The final receipt probe targets its actual `advisor:<requestId>` key.
They compare item/source/link/history/artifact/receipt tables before and after the
failure, then prove recovery and replay.

and a 1 GiB Node heap. Broad builds/tests belong in CI.
