# Local review before push

Use independent subagents to catch problems before the first reviewable push. For an already pushed PR, complete missing local coverage on its stable candidate while existing CI runs; do not request duplicate remote reviews. Reuse earlier independent local reviews that cover the required scopes and candidate, including verified follow-ups.

- Give reviewers the same base and candidate SHA, or a recorded working-tree fingerprint covering all intended tracked and untracked content. Include the actual diff, task requirements and repository instructions. Keep that candidate stable while they read; later edits need delta verification.
- Run two read-only reviewers concurrently within host capacity: one examines correctness, integration and affected callers; the other examines claimed behavior, test adequacy and failure cases. Reviewers must be independent of implementation in their assigned scope. Add a focused security reviewer for concrete security/permission/data risks. Focused roles alone do not satisfy land-pr's independent full-pass requirement.
- Use only delegation tools actually exposed and permitted by the host; the tool ceiling does not grant runtime authority. Reviewers must observe offline/live-test and resource limits; do not start simultaneous broad test suites. If delegation is unavailable or denied, report the missing local review and continue other permitted preparation. Do not bypass restrictions through another CLI, claim self-review is independent, or claim local coverage completed; obtain the missing review through an authorized host before the reviewable push.
- Require reports to identify reviewed scope and candidate, concrete findings with severity, location, failure scenario and evidence, and any coverage limits. Consolidate overlapping findings, fix valid blockers together, and record the evidence for rejected or already resolved findings. Keep reviewer identities, report references and finding dispositions with the landing evidence.
- After batched fixes, ask the relevant reviewer for one focused follow-up covering the delta, affected callers and prior findings. Retain unchanged reviewed coverage. Continue only for unresolved blockers or materially changed scope; do not chase cosmetic approvals or restart both full reviews after every edit. If a blocker persists without progress, report it instead of looping. Recheck that reports and follow-ups cover the actual candidate before pushing.

These local reviews improve the candidate; they do not replace trusted Centaur approval, change its request timing or configuration, or permit merge without land-pr's final gate.
