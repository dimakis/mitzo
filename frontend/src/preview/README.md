# Responsive chat preview

Run `npm run dev:ui-preview`, then open `http://127.0.0.1:3102/ui-preview.html`.
This renders the actual `ResponsiveChatView`, shared shells and sample conversations.
Its transport is simulated. No real account, provider, model or service is contacted.
The production entry point does not import these substitutes.

The retained Symposium sample starts with a compact participant header and one
Agents view. Inspect sharing controls, preview an agent's conversation independently,
and open fresh Add agent setup. Choose ordinary account/model/thinking intent,
Run on, purpose and full/selected/brief-only context. The review action is unavailable:
no trusted source/capacity/preparation owner is installed. This preview does not
fabricate a frozen review, an allocated session or a generated response.

The main transcript has no permanent All/agent tabs or separate recipient form.
Use @ in the actual shared composer to choose a recipient. The retained native
adapter still supports one recipient and explicit approval only; separate drafts,
queue receipts, Approve, Send, exact Stop and uncertainty remain with its original
owner. Conversation previews never change the composer recipient. Voice is unavailable
in this preview because no voice service is connected.

Earlier native configuration controls remain under Agents → Chat settings for
retained ownership/recovery. Their existing specialized fixtures still simulate
native Add/Approve/Send/Stop. They are not the approved ordinary fresh-agent allocator,
and do not prove replacement-route or account/runtime qualification.

Check 320px and 390px mobile and wide desktop, light/dark and alternate accents/fonts.
The automated all-intercept `symposium-approved-design` checks cover these actual
screens and save screenshots. Fixture banner hiding during capture affects no product
surface. Authentication, persistence, capacity, cancellation cleanup and live execution
still require their own evidence. Canonical staging and its pipeline remain stood down.
